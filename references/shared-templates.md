# 공동 기획·실행 양식

아래는 필요한 항목을 빠뜨리지 않기 위한 작업 양식이다. 전부를 빈칸 채우기식으로 사용자에게 보내지 마라. 작은 과업은 압축하고, 정보가 없는 항목은 미확인·제안·결정 필요로 표시하라.

## 1. 공동 기획안

- 과업 / 기준일 / 버전:
- 사용자가 요청한 결과와 기한:
- 이번 의제의 주민 문제와 목표 변화:
- PI의 중심: 실제 모습 / 바라는 정체성 / 확인된 주민 경험:
- 확인된 사실과 출처·확인일:
- 사용자 결정 / 제안 / 미확인 사항:
- 이번 실행 범위와 범위 밖 항목:
- 핵심 메시지와 이를 뒷받침할 정책·행동:
- A: 해결·결정할 의제와 산출물:
- S: 준비·현장·후속의 시점과 동선:
- V: 실체를 보여 줄 장면·자료·제작물:
- C: 참여·경청·응답·경험 확인:
- N: 필요한 역량 / 현재 근거 / 빈틈 / 확보 책임:
- 총괄·AI 작업 담당 / 실제 책임자·결정권자:
- 선행 조건과 교차 검토:
- 필요한 승인 / 이미 받은 승인과 범위:
- 완료 조건과 확인할 증거:
- 위험·대안 / 다음 확인:

## 2. 담당에게 넘기는 위임 계약

공동 기획안의 최신 버전과 필요한 자료만 함께 제공하라. 민감정보를 불필요하게 복사하지 마라.

“이번 과업은 [목적]이며 [기한]까지 [결과물]이 필요합니다. 공동 기획안은 [내용/링크·버전]입니다. 당신은 [담당 역할]을 맡아 [구체적인 질문]을 해결하고 [완성 산출물]을 만들어 주세요.
확인된 사실은 [근거]이며 [사항]은 아직 제안/미확인입니다. [선행 입력]에 의존합니다. [다른 담당]에게 [입력]을 전달해야 합니다.
허용된 행동은 [범위]입니다. [게시/발송/일정 변경 등]은 승인되지 않았거나 [정확한 승인 범위]에서만 가능합니다. 정책 결정이나 새 약속은 대신 확정하지 마세요.
완료 시 [검증 방법·증거]와 결과물 전체 또는 열 수 있는 링크를 주세요. 유용한 결과, 변경·충돌·장애, 추가 승인 필요는 즉시 총괄에게 보고하세요. 사용자에게 별도 약속을 하거나 범위를 넓히지 마세요.”

담당의 반환 항목:
- 결과와 실제 산출물
- 근거·확인 시점·불확실성
- 수행한 행동과 수행하지 못한 행동
- 승인 또는 사람의 결정이 필요한 항목
- 다른 담당에게 영향을 주는 변화
- 다음 행동과 완료 증거

## 3. 실행 기록

각 실행을 아래 한 묶음으로 기록하라. 공개 결과물에 주민 개인정보나 내부 연락망을 붙이지 마라.

- 항목 / 담당 / 실제 책임자:
- 상태 / 기한·시간대:
- 선행 조건 / 승인 근거·범위:
- 실제 행동 / 실행 시점:
- 결과물·도구 결과·확인 자료:
- 확인한 범위 / 아직 확인하지 못한 범위:
- 다음 행동 / 담당 / 기한 또는 확인 조건:

예: ‘발행용 원고 완성’의 증거는 원고이고, ‘외부 게시 확인’의 증거는 실제 게시 결과·URL이다. 원고가 있다는 이유로 발행 완료로 기록하지 마라. 발송 도구의 성공은 발송 요청 수락의 증거일 수 있지만 독자의 열람이나 반응의 증거는 아니다.

## 4. 결정·승인 요청

- 무엇을 결정하거나 승인해야 하는가:
- 권고안과 대안, 차이·조건·위험:
- 실행할 행동, 대상·수신자·공유 범위·시점:
- 포함되는 정보와 중요한 약속:
- 결정을 기다리는 항목 / 먼저 진행 가능한 항목:

질문은 필요한 만큼만 묶어라. 실제 발송·게시 승인 요청에는 검토 가능한 내용과 정확한 대상이 있어야 한다. 캘린더 초대, 외부 연락, 자료 공유를 한꺼번에 포괄하는 모호한 “진행해도 될까요?”를 피하라.

## 5. 리더십 시그널 인계

- 현행 제호: 중랑시그널 시리즈의 리더십 시그널
- 이번 사례·변화 / 검증된 출처·시점:
- MSAVN(C)에서 드러나는 연결·충돌·조건:
- 중랑에 적용하기 전에 물어야 할 질문:
- 이미 결정·실행한 것 / 제안 / 미확인:
- 주민 경험과 조직역량에서 확인할 것:
- Do/不, 다음 실행·확인과 담당:
- 제작 형식·독자·분량 / 승인된 배포 범위:

이 묶음을 jungnang-signal에 넘겨 취재·편집·제작하라. 소수 사례를 보편적 성공 법칙으로 일반화하거나 리더십 시그널의 편집 권고를 확정 정책으로 쓰지 마라.

## 6. 실행 후 학습

- 계획한 변화와 실제 확인된 결과:
- 주민·참여자가 실제로 경험한 것과 근거의 범위:
- 메시지·일정·의제·비주얼 간 차이:
- N: 부족했던 사람·전문성·권한·자원·협업과 보완:
- C: 미응답 질문·후속 약속·참여의 빈틈:
- 유지할 것 / 바꿀 것 / 다음에 확인할 것:
- 다음 공동 기획에 반영할 수정과 담당:

사용자가 요청한 단위가 끝나면 남은 결정·의무와 실제 완료를 분명히 보고하라. 향후 확인이 필요하면 이유와 확인 조건을 제안하되, 이 양식 자체를 반복 예약의 권한으로 삼지 마라.
