# 메시지 준비·검토 절차

M 담당이 행사 말씀자료와 간담회 응답을 실제 정책·현장·조직역량에 연결하는 절차다. 총괄의 공동 기획안을 입력으로 삼고, 표현·디자인의 전문 기준은 jungnang-public-communication에서 읽어 적용하라. 작은 과업에는 필요한 단계만 압축하라.

## 1. 형식과 요청 정보를 먼저 구분하라

구청장 현장 발언을 돕는 개조식 말씀자료, 완전한 문장으로 읽는 낭독문, 영상 인사, 축전, 보도자료를 구분하라. 개조식 말씀자료를 요청받았을 때만 그 형식을 기본으로 삼아라. 분량은 사용자가 정한 발언시간과 진행 순서를 기준으로 잡고, 모든 행사를 같은 장수·문체로 만들지 마라.

제공 자료에서 다음을 추출하라. 이미 있는 정보는 다시 묻지 말고, 중요한 빈칸만 확인하라.

- 행사: 이름, 목적, 일시·장소, 화자, 발언시간·순서, 참석 범위와 규모.
- 메시지: 반드시 전할 한두 가지, 피할 표현·미확정 사안, 이번 발언으로 알릴 변화.
- 감사·격려: 이름·직책의 정확한 표기, 실제 기여와 그 근거, 언급 순서의 제약.
- 주민과 정책: 이전 건의, 구의 대응, 현재 상태, 아직 남은 문제와 다음 응답.
- 실행·현장: 이용 시설, 사업·지원·계획, 확인 가능한 현장 장면과 필요한 접근성.
- 참고 근거: 최신 수치와 기준일, 담당 부서, 첨부 자료, 승인된 원고·수정 사례.

미확인 사실을 질문 없이 채워 넣지 마라. 그 정보가 없어도 가능한 문안은 먼저 만들고, 내부 검토본의 해당 위치에 확인 필요를 표시하라. 확인되지 않은 이름·수치·새 약속은 외부 사용본에서 빼거나 사실확인이 끝날 때까지 보류하라.

## 2. 본문과 사실 참고자료를 분리하라

말할 본문에는 청중이 이해할 핵심만 담고, 정확한 숫자·기준일·출처·담당·상세 사업 상태는 사실 참고자료로 보존하라. 본문을 쉽게 쓰는 과정에서 의미나 규모를 바꾸지 마라.

주장별로 근거, 확인일, 확인 담당, 결정 상태, 허용되는 표현을 함께 점검하라. 특히 다음을 구별하라.

- 과거 성과 / 현재 운영 / 승인된 향후 계획 / 검토 중인 제안.
- 주민의 건의 접수 / 조치 착수 / 조치 완료 / 주민 경험의 개선 확인.
- 사업의 목표 / 실제 집행·참여·완료 수치.
- 행사일 / 문서 작성일 / 자료의 기준일 / 실제 확인일.

자료의 오래된 통계·직책·인구·사업 현황을 현재 사실로 재사용하지 마라. 날짜를 임의로 앞당기거나 소급하지 말고, 제공 자료의 날짜가 충돌하면 원자료와 담당자 확인을 통해 풀어라.

업무계획은 실적의 증거가 아니다. 계획 문서만으로 완료나 현재 추진 중을 단정하지 말고 최근 상태를 확인하라. 작성 예시에 적힌 미래 행사일·참석 인원도 실제 일정·참석 확정으로 옮기지 마라.

청중이 이용하는 시설·사업의 향후 시기와 규모를 말하려면 승인 상태, 담당·자원·재원 등 이행 조건을 A와 N에서 확인하라. 검토 중인 구상을 확정 일정이나 구청장의 새 약속으로 바꾸지 마라.

## 3. 사람·변화·책임이 보이게 문안을 구성하라

다음 흐름을 행사 목적에 맞춰 선택하라. 모든 요소를 기계적으로 넣지 마라.

1. 지금 이 자리에 모인 이유와 행사 의미를 짧게 열어라.
2. 확인된 사람과 구체적인 기여를 감사·격려하라. 실명이나 기여가 불명확하면 만들어 넣지 마라.
3. 주민이 제기한 문제, 실제 조치, 확인된 현재의 변화를 연결하라. 주민 반응이나 개선 효과가 확인되지 않았으면 조치 사실까지만 말하라.
4. 구의 지원과 협력은 참여자의 기여를 가리지 않도록 놓고, 공공 자원을 화자의 개인적 시혜처럼 표현하지 마라.
5. 남은 과제에는 승인된 다음 단계와 응답 경로를 붙여라. 담당·기한이 없으면 결정 필요로 남겨라.
6. 행사의 다음 순서와 어울리는 짧은 맺음으로 끝내라.

개조식 본문은 화자가 현장에서 핵심을 찾고 자기 말로 이어갈 수 있게 논점 단위로 나누어라. 실제 현장 장면·주민 발언·미담은 출처가 있을 때만 사용하라. 관행적인 인구 수식어, 슬로건, 성과 나열을 자동으로 끼워 넣지 마라.

간담회는 인사말과 별도로 요청별 응답안을 준비하라. 담당 부서가 확인한 범위에서 바로 가능한 조치, 추가 검토가 필요한 조치, 현재 곤란한 조치를 이유·조건과 함께 구분하라. 대안, 회신 담당과 기한은 확인된 것만 적고, 미결정 사항을 즉석 수락한 것으로 쓰지 마라.

## 4. 사실·화자·서식을 따로 검토하라

- 사실: 담당 부서 자료와 대조하여 이름·직책·행사일·숫자·사업 단계·약속의 근거를 확인하라. AI 점검을 부서 확인 완료로 기록하지 마라.
- 화자: 확인된 화자 명의와 승인된 발언·수정 사례로 어조와 판단을 검토하라. 부서 초안을 화자의 직접 수정본으로 취급하지 마라. 김현성 개인 문체를 구청장 발언에 자동 적용하지 마라.
- 표현: jungnang-public-communication으로 과장, 모호한 약속, 공공성·형평성, 듣기 쉬움과 원문을 살릴 대목을 검토하라.
- 현장: S의 시간·진행과 V의 장면·자료를 대조하고, C의 질문·미응답 및 N의 이행 조건이 문안과 맞는지 확인하라.
- 서식: 사용자가 제공한 현재 템플릿과 승인 기준을 우선하라. 참고 저장소의 서체·여백·버전별 변경을 구의 공식 표준이나 영구 지시로 승격하지 마라.

새 사실, 한 번의 문안 수정, 반복 확인된 화자 선호, 승인된 기관 기준을 서로 다른 근거로 다뤄라. 확정되지 않은 기준은 잠정 제안으로 표시하라.

## 5. 파일 실물과 사용 가능 상태를 확인하라

파일이 필요하면 요청된 형식에 맞는 문서 제작 절차를 사용하라. HWP/HWPX는 실제 생성·편집 도구와 검수 경로가 있을 때만 제공하라. 사용할 수 없으면 그 제약을 밝히고 가능한 편집용 DOCX 등의 대안을 제공하라. 확장자 변경만으로 변환하거나 열어 보지 않은 파일을 검수 완료라고 하지 마라.

렌더링이나 실제 앱으로 페이지 흐름, 잘림, 줄바꿈, 글꼴 대체, 표·기호, 제목·본문 구분을 확인하라. 원문 추출 대조로 누락·중복을 점검하고, 발언시간에 맞는지는 낭독·실측 또는 명시한 추정으로 확인하라. 하지 않은 검사를 했다고 쓰지 마라.

생성기의 XML 검사나 표지 미리보기만으로 파일 전체를 검수했다고 하지 마라. 생성 경로마다 검사 범위가 다를 수 있으므로 최종 파일 자체를 확인하라. 외부 변환 도구를 사용할 때는 원고의 전송·자동저장·잔존 위치를 먼저 확인하고 필요한 권한 절차를 지켜라. 오프라인 도구도 브라우저 저장소에 원고를 남길 수 있다.

외부 사용본을 내기 전에 다음 상태를 따로 확인하라.

- 작성 중 표시·확인 필요·작성자 메모가 남았는가.
- 사실확인이 끝났는가, 아니면 어떤 항목이 누구에게 대기 중인가.
- 화자 측의 판단·어조 확인과 필요한 사용 승인을 받았는가.
- 실제 제공 파일의 형식·본문·레이아웃을 확인했는가.

초안 작성, AI 검토, 부서 확인, 화자 확인, 사용 승인, 실제 발송·게시를 구별하라. 초안에 남은 확인 사항은 별도 검토 메모로 돌려주고, 이를 숨겨 완성본처럼 보이게 하지 마라. 문안·파일 작성 요청만으로 외부 발송·게시하거나 공식 기록을 바꾸지 마라.

## 6. 총괄에게 넘기고 다음 기획으로 연결하라

요청한 문안과 실제 파일, 핵심 수정 이유, 남은 사실·결정 확인, 후속 응답의 담당·기한을 전달하라. 발언 뒤 확인된 질문·오해·미이행 약속은 C와 A·N으로 되돌려 실행을 점검하라. 승인된 수정 사례는 출처·수정 주체·적용 범위를 함께 남기고, 사례 하나를 화자의 영구 문체로 일반화하지 마라.

방법론의 참고 출처와 적용 한계는 [출처와 적용 범위](source-basis.md)의 ‘메시지 준비 절차 참고’를 보라.
